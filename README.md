# weekly-report

Obsidian 스타일의 주간 업무 Markdown을 포인트허브 주간 보고용 Excel 통합 문서로 변환하는 Python CLI 도구입니다.

출력 통합 문서는 다음 두 시트를 생성합니다.

- `개발파트`
- `포인트허브_이슈사항`

## 설치

```bash
uv sync
```

## 실행

주간 폴더를 입력하면 내부의 `업무관리.md`를 우선 사용합니다. `업무관리.md`가 없으면 같은 폴더의 기존 형식인 `00.md`를 사용합니다.

```bash
uv run python convert.py /path/to/week-folder
```

Markdown 파일을 직접 지정할 수도 있습니다. `00.md`를 직접 넘긴 경우에도 같은 폴더에 `업무관리.md`가 있으면 `업무관리.md`를 우선 사용합니다.

```bash
uv run python convert.py samples/sample.md
uv run python convert.py samples/업무관리.md
uv run python convert.py /path/to/week-folder/00.md
```

출력 경로를 직접 지정하려면 두 번째 인자로 XLSX 경로를 넘깁니다.

```bash
uv run python convert.py samples/sample.md output/report.xlsx
uv run python convert.py samples/업무관리.md output/report.xlsx
```

출력 경로를 생략하면 문서 제목의 연도와 업무 수행 내역의 목요일 날짜를 기준으로 다음 위치에 저장합니다.

```text
~/Documents/크레디프/주간보고/{YYYY}/{MM}/포인트허브_주간보고_{YYYYMMDD}.xlsx
```

변환이 끝나면 생성된 XLSX의 절대 경로와 생성된 시트명이 출력됩니다.

```text
✓ 변환 완료
  · 생성 위치: /path/to/output/report.xlsx
  · 개발파트
  · 포인트허브_이슈사항
```

## 입력 Markdown 형식

파서는 두 가지 입력 형식을 지원합니다.

### 주간 보고 Markdown

일반 주간 보고 Markdown은 제목과 섹션을 그대로 보고서 모델로 파싱합니다.

```markdown
# 2026년 4월 3주 주간 보고

## 📌 이번 주 목표
- [x] 상용 정기배포 (04-16)

## 📋 업무 수행 내역
### 월 (04/13)
- [x] 시스템 파라미터 값 SafeDB 암호화 ⏱ 4h/4h (김학진) #보안

## ✅ 완료 업무
- 시스템 파라미터 값 SafeDB 암호화 (김학진)

## 🔄 진행 중 업무

## ⏭️ 다음 주 예정

## 📝 특이사항 / 이슈

## 🏖️ 휴가
- 5/18 김학진 휴가
```

지원하는 항목 형식은 다음과 같습니다.

- 체크박스: `- [x]`, `- [ ]`, `- [/]`, `- [-]`
- 일반 목록: `- 업무 내용 (김학진)` 또는 `- 업무 내용 — 비고`
- 키-값: `**잘한 점**: 내용`
- 시간/담당자: `⏱ 4h/6h (김학진, 고영중)`
- 태그: `#보안`, `#배포`, `#버그`, `#db`, `#기타`

### 업무관리.md 테이블

`# 업무 관리` 제목과 업무 테이블이 있는 문서는 `업무관리.md` 형식으로 인식합니다.

```markdown
---
주차: 2026년 5월 2주
기간: 2026-05-11 ~ 2026-05-15
---
# 업무 관리

| 순번 | 시작일 | 종료일 | 상태 | 업무내용 | 작업자 | 예상/실제 | 태그 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 05-11 | 05-11 | [x] | 암호화 대상 평문필드 set null 작업 정리 | 김학진 | 4/4 | #db |
```

이 형식은 테이블을 기반으로 다음 섹션을 자동 생성합니다.

- `📌 이번 주 목표`: 테이블의 모든 업무
- `📋 업무 수행 내역`: frontmatter의 `기간` 안에서 시작일~종료일에 해당하는 요일별 업무
- `✅ 완료 업무`: 상태가 `[x]`인 업무
- `🔄 진행 중 업무`: 완료가 아닌 업무

`⏳ 대기/조건부 작업` 섹션은 출력 모델에서 제외합니다. 그 외의 이슈, 차주계획, 기타, 휴가 섹션은 Markdown 섹션으로 함께 반영됩니다.

## 파싱 규칙

체크박스 상태는 다음 값으로 변환합니다.

| 입력 | 의미 |
| --- | --- |
| `[x]` | 완료 |
| `[ ]` | 미완 |
| `[/]` | 처리 |
| `[-]` | 취소 |
| `[>]`, `[<]`, `[!]`, `[?]` | 미완 |

담당자는 다음 위치에서 추출합니다.

- 체크박스 항목의 `⏱ 예상/실제 (담당자)` 표기
- 일반 목록 끝의 짧은 한국어 이름 괄호: `(김학진)` 또는 `(김학진, 고영중)`
- `업무관리.md` 테이블의 `작업자` 컬럼

`all`은 담당자 목록 집계에서 제외합니다.

## 태그 분류

업무 항목의 태그는 개발파트 시트의 소분류와 셀 내부 하위 항목을 결정합니다.

| 태그 | 소분류 행 | 셀 내부 하위 항목 |
| --- | --- | --- |
| 태그 없음 | 포인트허브 개발 | 일반 개발 항목 |
| `#보안` | 포인트허브 개발 | 보안 및 인프라 |
| `#배포` | 운영 및 장애 대응 | 배포 및 모니터링 |
| `#버그` | 운영 및 장애 대응 | 버그 수정 |
| `#db` | 운영 및 장애 대응 | DB 및 서버 관리 |
| `#기타` | 기타 | 기타 |

여러 분류 태그가 있으면 `#보안`, `#배포`, `#버그`, `#db`, `#기타` 순서로 우선 적용합니다. `#todo`, `#important` 같은 보조 태그는 분류에 사용하지 않습니다.

## XLSX 매핑

### 개발파트

`개발파트` 시트는 코드에 정의된 고정 레이아웃을 사용합니다.

| 행 | 중분류 | 소분류 | G열 업무리스트 | I열 금주 수행 업무 |
| --- | --- | --- | --- | --- |
| 3 | 개발 | 포인트허브 개발 | `업무 수행 내역` 중 일반 개발/보안 항목 | `완료 업무` 중 일반 개발/보안 항목 |
| 4 | 개발 | 운영 및 장애 대응 | `업무 수행 내역` 중 배포/버그/DB 항목 | `완료 업무` 중 배포/버그/DB 항목 |
| 5 | 개발 | 기타 | `업무 수행 내역` 중 `#기타` 항목 | `완료 업무` 중 `#기타` 항목 |
| 6 | AO운영 | 정기 업무 | 코드에 정의된 AO 정기 업무 고정 텍스트 | 코드에 정의된 AO 정기 업무 고정 텍스트 |
| 7 | AO운영 | 비정기 업무 | 빈 값 | 빈 값 |

휴가 항목은 개발파트 업무 목록에서는 제외합니다.

### 포인트허브_이슈사항

`포인트허브_이슈사항` 시트는 고정 셀을 사용합니다.

| 부문 | 금주 이슈 | 차주 이슈 |
| --- | --- | --- |
| 개발부문 | `D3` | `E3` |
| 운영부문 | `D5` | `E5` |

이슈 섹션 제목이나 항목에 `개발`, `운영`, `AO`, `금주`, `이번 주`, `차주`, `다음 주`가 포함되면 해당 부문/시점으로 분리합니다. 명확한 구분이 없으면 개발부문 금주 이슈로 처리합니다.

휴가는 6행 한 줄에 출력합니다. `## 휴가` 섹션이 있으면 그 내용을 우선 사용하고, 없으면 `업무 수행 내역`의 `[-] 이름 휴가` 항목을 사용합니다.

## 수동 검증

자동화된 테스트 스위트는 아직 없습니다. 파싱 또는 Excel 렌더링을 변경한 뒤에는 다음 명령으로 샘플 변환을 확인합니다.

```bash
uv run python convert.py samples/sample.md output/report.xlsx
uv run python convert.py samples/업무관리.md output/report.xlsx
```
